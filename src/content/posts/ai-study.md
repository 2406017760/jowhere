## RAG

### 步骤
1. 离线阶段：文档加载切分chunk。根据自然语义切分，并且设置一定overlap。然后用embedding模型向量化，存储在向量数据库
2. 在线阶段：提问后，用同样模型把问题向量化，然后做混合检索，RRF融合召回后根据相关性rerank
3. 生成：把检索到的内容和用户问题拼成 prompt，要求模型基于给定资料回答，不知道就说不知道，并且尽量附上引用来源

#### 离线阶段 - 索引生成优化

1. Multi-representation Index（多表示索引）  
Multi-representation Index 是为了解决单表示检索的一个矛盾：原文太长，嵌入向量容易稀释语义；原文太短，又丢信息。它的做法是用 LLM 为原文生成多个检索表示，比如摘要或假设性问题，用这些表示建索引。检索时用它们匹配，命中后回溯源文档，把完整原文交给 LLM 生成答案。本质上是检索和生成解耦。
2. RAPTOR（递归抽象处理树状检索）  
RAPTOR 可以看作 Multi-representation 思路的系统化升级。Multi-representation 是给单篇文档生成几个代理表示，让匹配更准；RAPTOR 则是用递归摘要把整个文档库组织成一棵语义树，检索时既能在叶子层拿细节，也能在高层拿宏观摘要。它解决的是多跳、整合型问题里‘只见树木不见森林’的问题。
3. ColBERT（Token级别上下文检索）
ColBERT 比普通单向量检索更耗存储和计算，因为普通做法是把文档所有 token 向量池化成一个向量，而 ColBERT 保留每个 token 的向量序列。好处是避免了压缩损失，查询里每个 token 可以各自去找最匹配的文档 token，保留细粒度匹配证据，而不是被平均成一个模糊的整体向量。代价是索引存储量大约变成 token 数倍，在线 MaxSim 计算也更重。

#### 在线阶段 - 检索优化

1. Ranking（排序）：对检索结果进行初步排序
精排前，RRF融合混合检索结果，计算排名召回
精排阶段，根据专门排序引擎或者LLM重排筛选
2. Refinement（精炼）：对检索结果进行过滤和优化
3. Adaptive Retrieval（自适应检索）：根据查询特征动态调整检索策略
